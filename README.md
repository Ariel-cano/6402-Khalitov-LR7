# ЛР7. Анализ каталога землетрясений USGS

Мини-проект по дисциплине «Инструментальные средства анализа данных».

## Данные

Significant Earthquakes, 1965–2016, US Geological Survey.

Источник: https://www.kaggle.com/datasets/usgs/earthquake-database

Лицензия набора: CC0. Исходный CSV содержит 23 412 записей и 21 столбец. Для анализа отобраны события типа Earthquake с магнитудой от 5,5.

## Вопросы исследования

1. Как менялось число зарегистрированных в каталоге землетрясений по годам?
2. Как распределены магнитуды и как они связаны с глубиной?

## Структура

- `data/raw_dataset.csv.dvc` — описание версии исходного CSV.
- `notebooks/analysis.ipynb` — загрузка, очистка, анализ, три графика и выводы.
- `requirements.txt` — используемые зависимости Python с версиями.
- `.dvc/config` — настройка локального хранилища.
- `docs/` — отчёт и материалы для защиты.

## Подготовка и анализ

Даты двух форматов приведены к единому типу, проверены пропуски и дубликаты. Исключены 180 событий других типов; осталось 23 232 землетрясения. Пропусков в обязательных для анализа полях и полных дубликатов не обнаружено. Пропуски вспомогательных полей сохранены, эти поля не используются в исследовании. Отрицательная глубина −1,1 км не удалялась автоматически: её знак сам по себе не подтверждает ошибку записи.

В Pandas рассчитаны годовые числа событий, распределение магнитуды по интервалам и корреляция глубины с магнитудой. Годовые числа проверены одним SQL-запросом в SQLite. Построены линия по годам, гистограмма магнитуды и диаграмма плотности по глубине и магнитуде.

## Результаты

Минимальное годовое число записей составило 233 в 1966 году, максимальное составило 713 в 2011 году. Доля событий с магнитудой от 5,5 включительно до 6,0 составляет 68,6 %, медиана магнитуды равна 5,7. Корреляция Пирсона между глубиной и магнитудой составляет около 0,023, выраженная линейная связь не обнаружена. Результаты относятся к выбранному каталогу и не доказывают причинных связей.

## Версионирование данных

Git хранит код проекта и небольшой файл `data/raw_dataset.csv.dvc` с контрольной суммой, размером и путём к CSV. Сам CSV находится под контролем DVC и исключён из Git, чтобы версии данных не увеличивали историю репозитория. Файл `.dvc` позволяет проверить и восстановить нужную версию из хранилища DVC.

Хранилище `localstore` размещено в `DVCStorage/lab7` внутри проекта. В `.dvc/config` записан относительный путь `../DVCStorage/lab7`, который разрешается от папки `.dvc`. Папка `DVCStorage/` исключена из Git и обхода DVC через `.gitignore` и `.dvcignore`.

После добавления или изменения исходных данных выполняется `dvc push`: он сохраняет версию CSV в локальное хранилище. Команда `git push` отправляет код и метаданные в GitHub. Локальное хранилище не загружается на GitHub.

## Воспроизведение

Нужны Python 3.10, Git и доступ к папке хранилища DVC.

```powershell
git clone https://github.com/Ariel-cano/6402-Khalitov-LR7.git
cd 6402-Khalitov-LR7
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

До восстановления CSV скопируйте папку `DVCStorage` с исходного компьютера в корень клонированного проекта. Одна копия GitHub-репозитория не содержит CSV или хранилище. Затем выполните:

```powershell
.\.venv\Scripts\python.exe -m dvc pull
.\.venv\Scripts\python.exe -m ipykernel install --user --name lab7 --display-name "Python (lab7)"
```

Если хранилище расположено в другой доступной папке, вместо копирования настройте путь только для своего компьютера:

```powershell
.\.venv\Scripts\python.exe -m dvc remote modify --local localstore url "D:/DVCStorage/lab7"
.\.venv\Scripts\python.exe -m dvc pull
```

Откройте `notebooks/analysis.ipynb` в PyCharm или Jupyter, выберите окружение `.venv` либо ядро `Python (lab7)` и выполните Restart Kernel & Run All. Ячейки запускаются сверху вниз; первая ячейка находит данные при запуске из корня проекта или папки `notebooks`. Папка `.venv` и настройки локального пути не включаются в Git.

## Проверка

Ноутбук выполнен в новом ядре без ошибок. В отдельной копии проекта проверено восстановление CSV через `dvc pull` без исходного CSV и кеша: SHA256 восстановленного файла совпал с исходным. Группировки Pandas и SQLite дали одинаковые годовые числа, сумма равна 23 232.
